# CleanTech Finance v0.5 五轮双盲 QA 与迭代评估报告

报告日期：2026-08-04

评估范围：本地企业工作站、证据控制、内容授权、Deal 与受控 screen-grade 估值

数据性质：企业名称、业务、财务、可比公司、授权和补件均为 **Synthetic**；HTTP、浏览器、文件哈希、版本链和测试结果来自真实本地执行

## 执行结论

五轮“企业提交 → FA 盲测 → 精确追问 → 企业补件 → 定向工程修复 → 独立重放 → 完整门禁”已经执行完毕。工作站已经从“可展示的本地工作台”推进到“可用合成材料稳定验证关键控制的内部工具”：材料可以原样接收和哈希留痕，候选证据不会自动升级为事实，FA 可以留下逐字问题和补件回执，授权冲突会阻断动作，Deal 与 Company 相互隔离，估值输入经过人工确认后由服务端重建计算，并保留不可变版本、幂等和并发冲突控制。

本报告不能证明产品已经经过真实企业数据验证，也不能把五轮合成案例解释为正式估值、投资判断、信用判断、综合风险评级或可公开发布的认证结果。当前最准确的成熟度判断是：

- **内部演示和合成 QA：可用。** 五轮焦点回归均已通过，最终完整测试集为 403 项。
- **受控真实企业试点：可以开始，但必须由人负责授权、事实确认和结果复核。** 建议以 2–3 家已签署数据与使用授权的企业启动。
- **多人生产系统和真实材料公网托管：尚未就绪。** 身份、RBAC、持久化补件中心、云端数据隔离、审计与运营机制仍不完整。

## 第五轮关键结果

第五轮首次把 Deal 与受控估值作为主链路进行完整测试。初始 FA 只看到 8 个合成首包文件，在真实 loopback HTTP 中建立：

- Case：`case-20260804-99d9fc5072`
- Deal：`deal-20260804-6d3051b880f4`
- Valuation：`valuation-47603e4eba278a0e`

146 个候选输入不能计算，HTTP 返回 400；FA 通过 UI 人工确认同一业务 payload 后，旧实现能得到 screen-grade 结果，但它在估值日 2026-06-30、首个预测期 FY2027E 的情况下静默使用 1/2/3 折现指数，并仍将 Calculation Integrity 标为 passed。这被列为 S1，因为它可能实质改变每期 FCFF 和终值的现值。

企业角色只看到 7 个逐字问题，补交 9 个文件，其中 H2 2026E stub 的三情景 FCFF 为 23.000 / 27.950 / 31.500 CNYm，并提出 0.5 / 1.5 / 2.5 / 3.5 年折现指数。补件始终标为 candidate，`confirm_inputs=false`，没有自动进入模型。

修复后的独立回放使用 17 个原样文件，建立：

- Case：`case-20260805-9dbb8c4a4e`
- Deal：`deal-20260805-c26ceb6c3711`
- Valuation：`valuation-cf48a22919308733`

回放结果：

| 场景 | DCF EV（CNYm） | Equity value（CNYm） |
|---|---:|---:|
| Downside | 561.47 | 527.47 |
| Base | 1,017.23 | 983.23 |
| Upside | 1,503.27 | 1,469.27 |

Trading Comps EV 保持单独展示为 862.40–931.00 CNYm；没有把 DCF 与 Comps 加权或汇总成一个“正确价值”。原始候选仍以 400 拒算；把旧 07 文件仅改为 `confirm_inputs=true`、但不提供 timing 时，同样在请求边界 400 拒绝且不新增版本。修正后输出明确披露 `explicit_per_period`、四个期末日、四个指数和来源 input IDs；FCFF 与终值均使用最后一期 3.5 指数折现。

安全与状态控制也在真实 HTTP 中复测：浏览器提交计算对象被 403 拒绝；旧版本号和错误哈希均 409；完全相同的幂等重放返回同一版本；Agent approval 路由不存在；`internal_only` 可输入但持久化为既有 canonical `internal`。XLSX 展示逐期指数、期末日、input ID、source ID、locator、as-of 和公式，不把浏览器结果当作可信计算。

## 用户操作与补件记录

五轮首轮问题登记共有 44 条；实际发给企业侧并形成补件响应的逐字问题为 39 条。企业首包与补件合计 76 个文件。每一个问题都保留下列字段：逐字问题、缺口、所需材料、追问原因、对判断的影响、责任角色、状态和局部重算范围；企业动作日志保留查看、准备、上传和说明行为。

第五轮 7 个问题覆盖：

1. 法律主体、100% 股权范围、standalone 排除项和授权版本；
2. 历史、LTM 与预测财务底层来源、LTM 月度构成、口径及 CapEx/营运资本符号；
3. H2 2026 stub 与首期折现时点；
4. WACC、永续增长、退出倍数和判断性假设的人工作用域；
5. EV→Equity 六项余额、权属、受限状态及分类；
6. 五家可比公司的 EV/EBITDA 底表、核心/次级分类和异常值规则；
7. 仅内部 screen 使用，禁止外部流转、正式意见和公开发布。

响应结果为 2 answered、5 partial。所有回执均保持 candidate；真实签名、银行函证、合同、权属、税务文件、真实资本市场数据和 FA 正式接受均未被伪造。第五轮初始问题 Q02 把七个期间误写成“八项财务序列”，属于本轮协调文本的 S3 记录问题；响应按八个财务字段执行，未影响代码计算，但模板应改成“七个期间、八个财务字段”。

逐字记录和材料哈希可在各轮 `fa-initial`、`company-supplement`、`fa-postfix` 目录中复核；本报告不重复粘贴全部长问题，以免总报告掩盖原始审计记录。

## 已经稳定具备的能力

1. **本地材料工作区。** 支持允许格式、大小限制、原始字节、MIME、SHA-256、artifact ID、版本和识别候选；文件增加不会自动推进交易。
2. **候选—事实边界。** 管理层陈述、Agent 输出和企业补件均保持候选；只有显式人工确认的、带来源的估值输入可进入公式。
3. **缺口与问题链。** 可根据阶段、财务口径、证据冲突、授权和估值要求生成精确追问，记录责任人、材料要求和重算范围。
4. **证据控制。** 对 manifest mismatch、真实重复、结构化冲突、来源权威和版本差异 fail closed，不把缺失值解释为零或不适用。
5. **六类内容授权。** 录音、内部分析、公开发布、品牌、翻译和 AI 媒体分别判断；Agent 不能通过自我声明扩大权限；访谈原话只证明“说过什么”。
6. **Deal 与估值隔离。** Company、Case、Deal 和 Valuation 分开持久化；交易阶段只由人确认；不可变版本、哈希链、幂等键和并发检查有效。
7. **受控估值 P0。** Trading Comps、FCFF DCF、三情景、EV→Equity、WACC×增长和 WACC×退出倍数敏感性可由服务端确定性重建；方法保持并列，不加权。
8. **DCF timing 控制。** 非年末估值必须有完整、来源化、人工确认的逐期指数；三情景必须一致；自由文本 FY 标签不能触发推断；终值使用同一 timing。
9. **可审计导出与简化 UI。** XLSX 保留公式与来源；Deals 页面支持 3–5 期。真实 Chromium 验证 4/5 期会出现并变为必填，切回 3 期会隐藏并移除 required；未确认输入前计算按钮禁用，页面无自身错误日志。

## 仍然缺少的部分

### 上真实企业前必须补齐

- **真实企业授权与数据试点。** 目前没有真实企业数据、真实签署授权、真实银行/合同/税务/市场来源，也没有正式 FA model tie-out。
- **补件中心持久化状态机。** `gap_detected → request_drafted → request_sent → partially_submitted → submitted → needs_revision → accepted / rejected / waived` 尚未成为完整对象、API 和企业端 UI。
- **Request–submission–evidence 关联。** 当前报告能记录问题与回执，但产品内还不能把每个补件版本、哈希、审核结论和 accepted evidence 原子化关联。
- **局部重算依赖图。** 已能记录“受影响范围”，但没有持久化 dependency graph 自动选择重算节点。
- **真实身份与 RBAC。** loopback UI 仍使用固定本地 FA 身份；没有企业账户、SSO、多人权限、职责分离和全量人员级审计。

### 上多人生产和公网前必须补齐

- 真实材料的加密存储、密钥、租户隔离、备份恢复、保留/删除策略、恶意文件扫描和可观测性；
- 云端数据库、对象存储和后台任务，而不是把本地 workspace 或私有 RAG 直接搬到 Vercel；
- 正式审批与对外发布工作流、法律文本、数据处理协议和事故响应；
- 授权过期、撤回、主体变化以及历史已批准版本的影响传播。

### 产品路线图仍未自动化

- 端到端已验证的财务维度仍只有盈利/单位经济性、现金流/资金缺口；另外四个财务维度仍是输入蓝图。
- ESG、清洁技术影响和出海准备度仍是证据框架，不是自动认证。
- DOE ARL 17 维只有检索脚手架，不输出 ARL 1–9 分数。
- 真实市场可比公司、交易先例、项目级 DCF/NAV、reverse DCF 和正式模型校验尚未实现或未接入许可数据源。
- 公共 Vercel 页面仍是静态/浏览器本地演示，未连接本地企业事实库、私有 RAG 或真实 Deal store。

## 建议的下一阶段

建议停止继续扩大合成案例数量，转入小规模、强授权的真实试点：选 2–3 家不同阶段的清洁技术企业，每家指定企业材料负责人和 FA reviewer，只导入已经授权的最小材料包。先完成补件中心对象、状态机、企业提交 UI、人工审核动作、request/submission/evidence linkage 和局部重算依赖，再把真实材料放入系统。

试点成功标准不应是“系统给出一个分数”，而应是：材料来源可追溯；关键缺口被发现；问题对企业可理解；补件版本和哈希可回放；FA 能解释采用/拒绝理由；受影响计算被准确重跑；未经授权的动作全部阻断；同一输入在不同 Agent 下得到大体一致的事实层与确定性结果。模型智力允许影响候选解释与问题措辞，但不应影响哈希、规则门禁、公式、权限和事实状态。

## 最终边界声明

五轮结果证明的是软件控制在合成压力案例和真实本地执行下的行为，不是任何企业的真实性、商业质量或可投资性。估值结果只用于 screen-grade 内部流程演示，不是正式估值意见。系统没有生成投资、信用或综合风险评级，也没有把红/黄/绿证据信号汇总为总分；没有批准或执行公开发布。
